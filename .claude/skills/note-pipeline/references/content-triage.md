# 콘텐츠 트리아지 — 노트 생성 전 가치 판정

노트를 만들기 **전에** 이 문서로 판정한다. R1 Reduce 보다 먼저 실행한다.

목적은 두 가지다.
1. 광고·스팸이 `wiki/concepts/` 에 개념으로 승격되는 것을 막는다.
2. 원문에 없는 내용을 노트가 지어내는 것을 막는다.

## 왜 필요한가 — 실제 사고 2건

**사고 1 — 에러 페이지에서 노트 5개 환각 (2026-06-11)**
`clippings/20260611-medium.md` 의 본문 전체는 Medium 500 에러 페이지였다(41단어).
그런데 note-maker 가 URL 슬러그(`맥킨지가-openai-자회사에-줄을-선-진짜-이유`)만 보고
`wiki/concepts/20260611-distribution-as-moat.md` 를 만들었다. "정의", "핵심 속성" 3개
불릿, `relations` 의 `evidence: "구체적 사례: 맥킨지의 OpenAI 대리인 전략"` 까지 완비된
노트였고, **원문에 그런 내용은 한 글자도 없었다.** 총 5개 노트가 이렇게 생성됐다.

→ 이제 VERIFY 게이트(`scripts/content_validation.py`)가 대부분을 막지만, 게이트를
  통과한 짧은 본문에서도 같은 유혹이 생긴다. **원문에 없으면 쓰지 않는다.**

**사고 2 — 스팸 스레드가 개념 노트로 승격 (2026-06-11)**
`clippings/20260611-52-19-72.md` — "52세 주식 투자 19년 자산 72억 / 나는 이 5가지만
지킨다" 42단어짜리 전형적인 주식 리딩방 유인 스레드가
`wiki/concepts/20260611-stock-trading-execution-strategy.md` 로 승격됐다.

→ 검증 가능한 근거도, 출처도, 재현 가능한 방법론도 없는 주장이었다.

## 판정 — 3단계

### 1) 본문 신뢰도 확인

먼저 클리핑 프론트매터를 본다.

- `status: fetch_failed` → **노트를 만들지 않는다.** 파이프라인이 이미 걸렀어야 하지만,
  수동 실행이라면 여기서 멈춘다.
- `content_warning: too_short` 또는 `low_confidence` → 본문이 부실하다.
  **원문에 명시된 것만** 쓰고, 노트 개수를 최소로 한다(wiki 1개 또는 garden 1개).
- 본문에 `Warning:`, `Sign in`, `Enable JavaScript`, HTTP 에러 코드가 보이면
  추출 실패를 의심하고 멈춘다.

**절대 금지**: URL 슬러그·제목·도메인명만으로 내용을 추론해 노트를 채우는 것.
원문이 부실하면 부실한 대로 짧은 노트를 만들거나, 아예 만들지 않는다.

### 2) 광고 / 유용 분류

**📢 광고·스팸** — 다음 중 다수가 해당:
- 자기 홍보가 **핵심 의도** — 하나의 상품·계정·서비스를 팔기 위해 존재하는 글
- "지금 시작하세요", "DM 주세요", "무료 체험", 가격 제시가 본문을 지배
- 링크 덤프 — 맨 URL 하나 또는 한 줄 소개뿐, 옮겨 쓸 내용이 없음
- 근거 없는 최상급 표현("혁명적", "게임체인저", "이것만 있으면 됨")
- 수익·성과 자랑으로 신뢰를 만들고 방법은 알려주지 않음 (리딩방 유인의 전형)
- 방법론도, 데이터도, 재현 가능한 절차도 없음

**📚 유용** — 다음 중 하나라도 해당:
- 다른 일에도 옮겨 쓸 수 있는 방법론·워크플로·체크리스트
- 구체적 수치·데이터·벤치마크·비교
- 도구를 **사용법과 함께** 설명하고, 언제 대안보다 나은지 밝힘
- 정책·규제·기술 사실 (출처가 벤더여도 무관)
- 트레이드오프를 솔직하게 다룬 분석

**⚖️ 경계** — 라벨과 출처를 남기고 저장:
- 벤더 문서지만 실제 스펙이 있음 → `useful (vendor source)`
- 본문은 알찬데 끝에 홍보가 붙음 → 알맹이만 취하고 "말미 홍보" 기록
- 마케팅 비교표지만 데이터는 정확 → 데이터만 취하고 편향 표시

### 3) 처리

| 판정 | 처리 |
|---|---|
| 📚 유용 | 정상 6 Rs 진행. 프론트매터에 `classification: useful` |
| ⚖️ 경계 | 진행하되 알맹이만. `classification: useful` + `classification_note` 에 편향 기록 |
| 📢 광고 (옮길 내용 없음) | **노트 생성 안 함.** 클리핑은 지우지 않는다 |
| 📢 광고 (부분적으로 쓸 것 있음) | garden 노트 최대 1개만. `classification: ad` + 사유 1줄 |

**광고 클리핑을 자동 삭제하지 않는다.** 라벨만 붙이고 출처를 보존한다 —
나중에 판정을 다시 볼 수 있어야 한다.

## 프론트매터 필드

노트를 생성할 때 다음을 추가한다.

```yaml
classification: useful          # useful | ad
classification_reason: "재현 가능한 7단계 방법론 제시"   # 한 줄
```

`classification: ad` 인 노트는 `status: draft` 로 두고 퍼블리시하지 않는다.

## 시한성 정보 — 알림 큐

원문에 다음이 있으면 노트 생성과 별도로 알림 큐에 넣는다.

```bash
python3 scripts/alerts.py add "<한 줄 요약>" --category <카테고리> --source <클리핑 슬러그>
```

카테고리: `security`(보안 취약점·유출) · `account_expiry`(API 키·도메인·구독 만료) ·
`project_risk`(진행 중 프로젝트에 영향을 주는 정책·경쟁 변화) · `deadline`(마감·행사일)

날짜가 명시된 것만 넣는다. 추측하지 않는다.

## 노트 파일명 — 클리핑 슬러그 재사용 금지

노트 파일명을 클리핑 파일명과 같게 지으면 Quartz 의 shortest 해상도가 `[[슬러그]]` 를
노트와 클리핑 중 어디로 보낼지 결정할 수 없다. 링크가 예측 불가하게 걸린다.

실측(2026-08-27): 45개 충돌 → 본문 ambiguous 링크 1,879건. 그중 하나
(`20260613-ep98-ko-transcript`)만 727회 참조되고 있었다.

노트 파일명은 **내용을 서술하는 슬러그**로 짓는다.

```
클리핑 : 20260613-ep98-ko-transcript
노트   : 20260613-context-window-as-attention-budget   ← 이렇게
         20260613-ep98-ko-transcript                   ← 금지
```

확인: `python3 scripts/audit_clippings.py --collisions`
